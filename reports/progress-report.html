CTM PawnTrack: Project Progress Report

Web-based pawnshop management system for CTM Pawnshop (Kiblawan, Davao del Sur)
Report date: October 29, 2026  |  Prepared for: Project Adviser
Live system: https://ctm-pawnshop.vercel.app  |  Source code: github.com/mtbdiaz/CTMPawnshop (branch main)

1. Summary

CTM PawnTrack replaces the originally planned JavaFX desktop application with a web application that runs in a browser. It covers all 40 product backlog items (PB-1 to PB-40) across the ten sprints in the project plan, and a later improvement pass requested by the owner added 19 further changes (archiving, customer scoring, a new loan flow, thermal and A4 printing, and others).

  • Status: every backlog item is implemented and deployed. The latest production deployment of main succeeded on October 27, 2026.
  • Size: about 11,400 lines of application code, 19 database migrations, about 30 screens, 155 automated tests (all passing).
  • Data: the live database now holds a demo data set of 1,241 loans, 420 customers and 1,290 appraisals covering July 1 to October 27, 2026, so the system can be shown with realistic activity.
  • Open items: a few business rules were set by assumption and need CTM's confirmation (section 9). A hands-on walkthrough of the live site by each user role has not yet been done.

2. Technology and architecture

LayerChoice
ApplicationNext.js 16 (App Router) with TypeScript and Tailwind CSS
Database and loginSupabase (PostgreSQL, Auth, Row Level Security, file storage for item photos)
HostingVercel, deploying automatically from GitHub
TestingVitest (unit tests), TypeScript type checking, ESLint, production build
RolesAdmin, Operator, Cashier, Appraiser. Access is enforced in the database (Row Level Security) as well as on each page, so hiding a button is never the only protection.

Key design decisions: every loan change (new loan, payment, renewal, redemption, default, reinstatement) runs inside a database function that checks the user's role and updates the loan, vault item, appraisal and cash ledger together, so the records cannot drift apart. Saved loans, payments and customer names are locked and cannot be edited directly.

6. Printed pawn ticket

CTM supplied its own pawn ticket form as a PDF (half-letter, landscape). The system now prints tickets on that form. Every word, box and line was placed at the exact position read from the PDF, and only the blanks are filled in from the loan: ticket number, dates, name, address, amount in digits and in words, interest rate, appraised value, item description, and the principal, interest, service charge and net proceeds table. A test print compared against the owner's PDF matched to within half a point (about 0.2 mm) vertically and 0.01 point horizontally. The long-text test (very long name, address and item notes) stays inside the boxes.

8. Quality and security

  • Automated tests: 155 unit tests in 28 files, all passing. Type checking, lint and production build are clean.
  • Database self-tests: 10 of 10 passed on the live database (for example, a cashier cannot change a saved loan, only an Admin can restore archived data, and every Admin edit needs a reason and writes before and after values to the audit log).
  • Data rules: Row Level Security is enabled on every table; no delete permission exists for staff accounts; every change is written to the audit trail.
  • Regular QA logs: QA_LOG.md records each audit pass, what was fixed and what was left open.
  • Secrets: a repository scan found no live secrets in tracked files. One earlier commit once contained a Supabase service key; it was removed, but it remains in the repository history and should be rotated in the Supabase dashboard.

9. Decisions and open items needing confirmation

Business rules set by assumption (please confirm with CTM)

  • Valuation: value = weight × price per gram for the karat; no purity multiplier. The earlier backlog item PB-14 was marked not estimable because the exact formula was never confirmed.
  • Interest after the due date: every 30 days, or part of 30 days, past the due date adds one full month of interest (5% of the remaining principal). There is no separate late-payment penalty fee; a flat or percentage penalty could be added if CTM wants one.
  • Default and forfeiture: a loan becomes defaulted the day after the 7-day grace period ends. Interest keeps accruing while it is defaulted.
  • Capitalizing: the new due date is the old date plus 30 days, or today plus 30 days if the loan is already past due.
  • Customer score weights: start at 60; +8 per on-time redemption; +3 per renewal (capped at +15); −6 for late payments; −15 for a reinstatement; −25 for a default; −10 if overdue now.
  • 21K and 18K prices: set as 21/24 and 18/24 of the 24K price.
  • Counterfeit check: now a manual flag by the appraiser, cleared by an Admin, because the purity-based check was dropped with the new formula.

Pawn ticket form questions

  • Net Proceeds is printed as principal minus service charge, because the system pays out the full principal and collects interest at redemption. Does CTM deduct interest in advance?
  • Service Charge prints 0.00 because the system has no such field.
  • Expiry Date of Redemption Period is the due date plus the grace period.
  • The form's wording was kept exactly, including "Thumbrark" and "has pledges to this Pawnee", which look like typos.
  • The back of the ticket (terms and conditions) was not in the supplied PDF and is not yet printed.

10. Known limitations

  • Default detection runs when staff open the loans page, not on a timer. A scheduled job is needed before real use.
  • Reminders are logged in the app only; no SMS or email service is connected.
  • AML check is a keyword-based placeholder, not a real sanctions-list service.
  • Live walkthrough: the development environment could not open the live site, so a hands-on check of every screen with each of the four roles has not yet been done. It is recommended before real use.
  • Not supported by the current design: items other than gold jewelry (phones, appliances), sale records, a voided-ticket status, e-wallet payments and cash-drawer counts.
